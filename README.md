# Karachi Rate Board

A free, always-on dashboard of Booking.com rates for the Karachi hotels with DHC rate letters.

- **Overview**: every hotel with its lowest rate for tomorrow night, the change since yesterday, last week and last month, a 30-day trend line, and a feed of every price change in the last 7 days.
- **Hotel page**: each room type (room-only and breakfast rates tracked separately) with its rate, the same three changes and a trend line, plus a 30-day chart of the hotel's lowest rate.

## How it works

| Part | What it does | Cost |
|---|---|---|
| `collector/collect.py` | Opens Booking.com in a headless browser and reads the room table of each hotel in `data/contract-hotels.json` (`--all-hotels` also reads every 3–5 star hotel in the Karachi search). Saves one snapshot to `data/snapshots/`. | free |
| `collector/build.py` | Compares the latest snapshot with the ones nearest 1, 7 and 30 days earlier and writes the small files in `docs/data/` that the dashboard reads. Folds snapshots older than 45 days into `data/archive/`. | free |
| `docs/` | The dashboard itself: plain HTML, CSS and JavaScript, no build step. | free |
| `.github/workflows/collect.yml` | Runs the two scripts every hour on GitHub Actions, commits the new data and publishes `docs/` to GitHub Pages. | free on a public repository |

Every snapshot prices the same stay: **1 room, 2 adults, 1 night, checking in the next day (Karachi time), in PKR**. So "vs last week" compares today's next-night rate with the next-night rate a week ago.

## Limits of the data source

- Booking.com has no free public API for rates, and its terms of use do not allow automated collection. This project reads the public website the way a browser does, at a low rate (one page per hotel, every hour). Booking.com can block it or change its page layout at any time; see "When Booking.com changes" below.
- Runs are hourly. GitHub can start scheduled runs late at busy times, and pauses schedules on repositories with no activity for 60 days (the hourly data commits count as activity).
- Prices are what Booking.com shows to a visitor from a US data centre (where GitHub's machines are). Pakistan-only deals or Genius member prices may not appear.
- Everything here is free. There is no paid fallback.

## When Booking.com changes

Every run writes `data/status.json` with one of these states, and the dashboard shows a bar across the top for anything but `ok`:

| State | Meaning | Bar | GitHub issue |
|---|---|---|---|
| `ok` | Rates read normally | none | closes any open one |
| `layout` | The search page loaded but hotel cards, names or prices could not be read | red | opened |
| `rooms` | Hotel rates read, but room tables failed on most hotel pages | red | opened |
| `blocked` | Booking.com showed a bot check | sand; red after 12 hours | opened after 12 hours |
| (no run for 3 hours) | The schedule stopped | sand | none |

The issue carries the `collector-broken` label and links the run. That run's `debug` download holds the HTML and a screenshot of the page Booking.com served, which is what's needed to update the selectors in `collect.py`. GitHub emails the repository owner when the issue opens.

## Setup

1. Create a **public** repository on GitHub and push these files to it (GitHub Pages is free only for public repositories on a free account).
2. In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. **Actions → Collect rates → Run workflow** to do the first run now. After that it runs every hour on its own.
4. The dashboard is at `https://<your-username>.github.io/<repo-name>/`.

Until the first real run finishes, the dashboard shows made-up sample data under a clear banner (`data/sample/`, generated by `collector/sample.py`).

## Run it on your own computer

```
pip install -r requirements.txt
python -m playwright install chromium
python collector/collect.py          # add --no-rooms for a quick hotels-only run
python collector/build.py
python -m http.server -d docs 8000   # then open http://localhost:8000
```

## Discounthotels.pk vs Booking.com

Every run also reads Discounthotels.pk's own rates for the same stay from the site's public API (`api.discounthotels.pk`), for every hotel mapped by `dhc_site_id` in `data/contract-hotels.json`. The site's prices include 15% tax, so they are shown before tax like everything else. **Lowest rates** and **Room by room** compare these with Booking.com, with a PKR difference column, a DHC lower/higher filter and a lowest/highest price sort.

## DHC rate letters vs Booking.com

The **Room by room** view compares every room type in the hotels' rate letters with the same room on Booking.com.

- `data/contract-hotels.json` lists the 13 hotels with rate letters, their Booking.com pages and the room types named in each letter, with the words used to recognise each room on Booking.com. It holds **no rates**.
- Every run, `collect.py` opens each of these hotels on Booking.com, and `build.py` writes `docs/data/contracts.json`: the matching Booking.com room, its price before tax for 2 adults (breakfast offer preferred) and its changes.
- The corporate/BRB rates live in a private rate sheet (`dhc-contract-rates.json`) that is **never committed or published**: `.gitignore` blocks it, and Ramada Plaza's agreement forbids showing its rates on any public platform. The dashboard reads it from a file you choose in your own browser and keeps it there.

Comparison rules: every rate is before tax, for 2 adults and 1 night. Booking.com shows Karachi prices with tax excluded; letters that quote tax-inclusive prices have the 15% tax taken out. Single-occupancy letters add the hotel's extra-person charge. Flags: Booking.com below the corporate rate, within 5% of it, or 5%+ above it.

The **Lowest rates** view (the landing page) puts each rate-letter hotel's lowest corporate rate (and lowest rack rate, where the letter gives one) next to its cheapest Booking.com room for 2 adults right now, and the lowest and highest Booking.com rate so far today (Karachi time). Rack rates are in the private rate sheet too.

If a room shows "No matching room", or Booking.com names a room differently, edit its `keys` in `data/contract-hotels.json`: each entry is a list of words that must all appear in the Booking.com room name, and `exclude` lists words that must not.

## Desktop app

`desktop/app.py` opens the live dashboard in its own window, with its own saved copy of the rate sheet. The **Desktop app** workflow builds it for Windows (`DHC-Rate-Board-Windows.exe`) and Mac (`DHC-Rate-Board-Mac.zip`) and attaches both to the `desktop` release. The app holds no rates and needs an internet connection; it is not code-signed, so Windows and macOS warn the first time it is opened.
